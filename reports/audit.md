# Main-v1 run audit

**Date:** 2026-10-26. The audit script is [`experiments/audit_runs.py`](../experiments/audit_runs.py); machine-readable hashes and counts are in [`data/curated/audit.json`](../data/curated/audit.json).

- Exactly **96** JSONL rows match the **96** pre-frozen matrix cells, in order, with no duplicate `(family, config_id, repeat_id)` and 24 rows per family.
- Every row uses `data_version=main-v1`, `backend=dask_local`, the frozen configuration and dataset bytes, and the pre-frozen family SLA. No row is voided.
- **96 successes, zero timeouts, zero OOMs, zero SLA misses.** Thus timeout censoring does not affect this table, and the observed failure count is insufficient for a learned failure model. No failure-rate improvement can be claimed from these runs.
- All engine durations are positive. `peak_memory_bytes` is null because the collector did not capture reliable peaks. During some 1 GB sort jobs Dask logged unmanaged-memory warnings and worker pauses around 776 MiB process memory; those successful jobs remain labeled success. The warnings do not establish spill or OOM.
- The model feature whitelist in [`safe_pipe/features.py`](../safe_pipe/features.py) contains only workload metadata and declared configuration resources known before a run. Actual duration, status, failure category, SLA miss, and peak memory are labels or post-run fields and cannot enter that feature matrix.

The raw JSONL and generated Parquet stay local and gitignored. The audited flat [`runs.csv`](../data/curated/runs.csv) is committed for other PCs; the local `runs.parquet` is regenerated by the audit script. This CSV contains the same 96 measured rows and omits the raw machine hostname.
